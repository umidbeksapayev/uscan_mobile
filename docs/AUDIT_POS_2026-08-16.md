## 3. Spec bo'yicha muhandislik e'tirozlari

Talab #34 ("overengineering qilma") asosida uchta bandga e'tiroz:

**3.1 `USBPrinter` — qurilmaydi.**
React Native/Expo'da USB printer Android'da native modul talab qiladi,
Expo Go/EAS'da qo'shimcha config plugin kerak, va real ehtiyoj yo'q
(Bluetooth + tarmoq yetadi). `PrinterTransport` interfeysi uni keyin qabul
qiladi, lekin bugun implementatsiya yozilmaydi.

**3.2 `ScannerManager` — to'liq manager emas, pipeline ajratish.**
Hozir 1 ta skaner bor. Manager 2-chi kelganda kerak. Lekin `onBarcodeScanned`
pipeline'ini UI'dan ajratish **bugun ham foydali** — `scanner.tsx` da
lookup/savat/navigatsiya mantiqi UI bilan aralashgan va HID qo'shish uchun
baribir ajratish shart.

**3.3 Bluetooth SPP skaner — oxirgi, va faqat ehtiyoj bo'lsa.**
Printer va skaner bitta `react-native-bluetooth-classic` instansiyasini
ulashadi. Ikkalasi bir vaqtda ulanganda kutubxona holati chalkashishi —
real xavf, va bu kutubxona `rc` versiyada. HID skanerlar bozorning ~90% i;
SPP'ni oldindan qurish xavfni tekinga sotib olish.

## 4. Kirill uchun texnik qaror (P0-2)

Termal printerda kirill chiqarishning ikki yo'li:

**A. Codepage (`ESC t n`)** — printer ichki shriftiga o'tkazish (CP866 = `n=17`,
CP1251 modelga qarab). Tez, oddiy, ~60 qator kod.
Kamchilik: `n` qiymati printer modeliga qarab farq qiladi; hamma printer
qo'llamaydi.

**B. Raster/bitmap (`GS v 0`)** — matnni rasm qilib chizish. Har qanday belgi,
har qanday printerda ishlaydi. Kamchilik: RN'da matn→bitmap render qilish
uchun canvas yo'q → yangi dependency yoki murakkab kod; 2–3x sekinroq.

**Tavsiya: A, sozlama bilan.** Printer config'iga `codepage` maydoni
(`auto | cp866 | cp1251 | ascii`) qo'shiladi, default `cp866`, test print
bilan tekshiriladi, ishlamasa foydalanuvchi `ascii` ga tushadi.
B varianti — kelajak bosqich, alohida qaror.
